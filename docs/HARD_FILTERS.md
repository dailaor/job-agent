# 硬筛选字段说明

职位和地点是主流程中的核心字段，但不足以承担可靠筛选。当前硬规则分为岗位目标、工作约束、风险排除和时效四组。

## 字段语义

| 配置字段 | 页面名称 | 判定方式 |
|---|---|---|
| `target_titles` | 岗位名称或方向 | 岗位标题至少命中一个；主向导必填 |
| `locations` | 工作地点 | 地点至少命中一个；留空不限 |
| `employment_types` | 职位类型 | 全职、实习、校招、兼职可多选 |
| `work_modes` | 办公方式 | 现场、混合、远程可多选 |
| `minimum_salary` | 月薪最低期望 | 已披露薪资上限仍低于期望时过滤 |
| `max_experience_gap` | 最多接受经验差距 | 岗位最低经验高出候选人年限超过该值时过滤 |
| `published_within_days` | 最近发布天数 | 已披露发布时间早于窗口时过滤；留空不限 |
| `excluded_keywords` | 排除关键词 | 在岗位名、公司或描述中命中即过滤 |
| `blacklisted_companies` | 公司黑名单 | 公司名命中即过滤 |
| `company_tiers.不投` | 不投公司档位 | 与黑名单相同是硬规则；其余档位只影响排序 |
| 候选人与岗位学历 | 学历要求 | 双方学历均可识别且候选人不足时过滤 |
| 岗位 `deadline` | 截止时间 | 明确过期时过滤 |

`company_tiers.优先` 和 `company_tiers.可接受` 不是硬规则；它们不能把能力不匹配的岗位变成“冲高”。

## 未披露字段策略

`unknown_field_policy` 有两个值：

- `keep`：字段缺失时先保留岗位，避免把渠道数据质量误当成用户不符合。默认使用此项。
- `reject`：对已启用的职位类型、办公方式、最低薪资和最近发布时间规则，如果岗位没有披露对应字段，则按硬规则不通过；岗位提供了 `deadline` 但格式无法解析时也会拒绝。

该开关不会把“岗位完全没有截止时间”直接判为过期，也不会因岗位未披露学历或经验就直接拒绝；学历和经验只在双方/岗位值可识别时比较。`keep` 只表示不因缺失直接过滤，不承诺改变 `confidence` 字段。

未知不等于不符合。页面必须把这一选择写清楚，不能用一个含糊的“严格模式”替代。

## 为什么不把这些都塞进首屏

岗位名称和地点决定搜索范围，使用频率最高，因此始终可见。职位类型、办公方式、薪资、经验、新鲜度和排除项在“更多硬性条件”中展开，沿用上次值。这样首次任务短，再次任务也无需重复输入，同时保留严格控制能力。

## 与策略的关系

顺序固定为：

```text
标准化岗位 → 硬规则 → 能力关系（冲高/持平/保底/不投） → 公司与新鲜度排序 → 策略配额
```

“冲刺优先、均衡匹配、保底优先”同时影响两个部分：

- 双向排序权重：冲刺模式使用 `人匹配岗位 35% + 岗位满足人 65%`，均衡为 `50% + 50%`，保底为 `65% + 35%`。
- 队列配额：分别提高冲高、持平或保底类别在每日清单中的比例。

其中“人匹配岗位”来自技能覆盖和经验差距；“岗位满足人”来自公司偏好、地点、薪资、职位类型、办公方式和新鲜度。两类权重与配额都位于硬规则之后，不能绕过地点、黑名单、截止时间等结论。

当前规则模式会在本机从可读 PDF/DOCX 中提取文本，并只从明确出现的受控技能词、工作年限表达和最高学历更新候选人档案；用户仍可在配置页校正。扫描版 PDF、复杂版式或未命中的表述可能无法提取，系统不会编造缺失经历，也不会假装已经调用大模型。未来接入 BYOK/Ollama 时，模型输出仍必须位于硬规则之后，并保留可解释证据。
