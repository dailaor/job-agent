# 职来 Agent

一个本地优先的求职决策工具：整理岗位，解释推荐理由与风险，核对来源证据，并记录投递后的进度。作品展示名为「好岗有据」，仓库和运行界面仍保留「职来 Agent」标识。

[下载 Windows 完整版](https://github.com/dailaor/job-agent/releases/tag/v0.3.0-alpha) · [下载纯前端演示](https://github.com/dailaor/job-agent/releases/download/v0.3.0-alpha/JobAgent-v0.3.0-alpha-frontend.zip) · [下载单文件 HTML](https://github.com/dailaor/job-agent/releases/download/v0.3.0-alpha/JobAgent-v0.3.0-alpha-standalone.html)

当前为 **v0.3.0-alpha**。重点是帮助用户判断“是否值得投”，不是默认批量代投；一键投递尚未开放。

## 本次更新

- **推荐页改为单卡浏览**：只展示高推荐岗位，两侧箭头切换；搜索和同团队体验筛选可用。
- **全部岗位保留完整列表**：高推荐、待核实、低推荐和未评估岗位都能查看，不因推荐页收敛而丢失机会。
- **新增求职进度维护**：记录岗位、阶段和备注，支持更新与筛选；兼容旧投递记录和回执。
- **重新划分页面职责**：主导航为智能推荐、全部岗位、求职进度、我的档案、设置。
- **视觉统一为深海蓝＋冷灰白**：替换树苗图标，减少重复介绍文案，保留决策信息与证据。
- **交付独立前端演示**：完整前端源码和单文件 HTML，无需后端、数据库或 API Key。

## 每个页面解决什么问题

| 页面 | 用户要完成的事 |
|---|---|
| 智能推荐 | 在少量高推荐岗位中，核对值不值得投以及还需确认什么 |
| 全部岗位 | 搜索所有已收录岗位，查看不同推荐度、来源和原岗位入口 |
| 求职进度 | 记录投了哪些岗位、当前阶段、后续沟通与备注 |
| 我的档案 | 管理简历、学历、技能、岗位方向、地点与工作体验偏好 |
| 设置 | 配置岗位渠道与执行选项；高级区保留情报库、运行统计、运行记录和实验执行工具 |

运行统计不再占据独立主导航，运行记录也不要求日常用户反复查看；需要维护渠道或排查异常时仍能进入。

## 智能推荐工作卡

### 不是一个总分，而是一组决策依据

| 决策点 | 卡片展示 |
|---|---|
| 待遇 | 已披露的薪资区间与计薪口径；展开核对发薪月数、奖金、股权与福利 |
| 可投门槛 | 当前档案与已知学历、经验要求的冲突，以及仍需确认的资格 |
| 能力关联 | 已关联的技能与档案尚未体现的缺口，不当作录用概率 |
| 值得了解的理由 | 与个人条件或偏好相关的事实，附可回查依据 |
| 风险与未知 | 信息未披露、能力缺口、体验冲突及待确认事项 |
| 工作体验 | 时间负担、工作节奏、职责质量、管理文化、成长性、稳定性六组信息 |
| 证据链 | 原文、出处、日期、公司、岗位族、用工类型与团队/城市范围 |
| 下一步 | 打开原岗位核实与投递；通过“记录求职进度”维护后续阶段 |

点击“依据”会展开详细信息、高亮相关来源并定位到首条证据。没有可信数据时显示待核实，不补造薪资、工时、总包或有效时薪。

### 什么会进入高推荐

推荐页只取当前规则结果 `decision.status=recommend`，界面标签为“优先了解”。它综合当前档案、已知门槛、能力关联、偏好支持与重要未知信息，不是历史综合分达到一个统一阈值。

待核实和低推荐岗位留在全部岗位中；没有高推荐岗位时明确显示空结果，不用低推荐卡补位。搜索、样本筛选或数据刷新后，卡片位置与箭头边界自动更新。左右键只在卡片区域响应，不接管其他输入框。

“已知门槛通过”**不保证招聘系统一定允许提交**。专业、毕业时间、岗位有效性等未验证条件仍需核实。全部岗位中的流程状态、历史双向评分与当前推荐度是不同字段，流程状态不等于真实提交资格。

### 工作体验为什么要保留来源

同公司、岗位族和用工类型一致，且团队、城市完整对齐的经历，才作为直接体验样本；缺少范围的内容只作背景参考，明确不一致的内容不拿来证明当前岗位。正职和实习不跨类型检索。

个人经历不能代表整个公司；过期、否定描述、多来源冲突和失效证据不能被当作可靠正向支持。用户仍需要向 HR 或直属负责人确认实际安排。

## 全部岗位与求职进度

![全部岗位：完整列表、来源、评估与原岗位入口](docs/assets/readme/job-pool.png)

全部岗位支持搜索和流程状态筛选，保留低推荐与未评估记录；“一键投递”按钮为明确禁用的预留入口，不会触发任何发送或提交操作。

![求职进度：阶段、更新时间、手工记录与旧回执](docs/assets/readme/progress.png)

求职进度支持八个阶段：**准备投递、沟通中、提交待确认、已投递、测评、面试、Offer、已结束**。备注最多 2000 字，同一岗位再次记录会更新原记录；阶段与备注在完整版存入本机数据库。

手工进度与旧执行状态分别保存。选择“已投递”只表示用户手动记录，不会伪装成招聘平台确认，也不会覆盖原始回执、外部 ID 或执行时间。旧异常或不确定状态谨慎映射为“待确认”。

手工维护过的记录不会再被旧实验执行队列继续消费。已经授权且开始的外部动作无法撤回；系统保留实际返回的回执，同时不覆盖人工维护的阶段和备注。

## 选择演示版还是完整版

| | 纯前端演示 | Windows / 源码完整版 |
|---|---|---|
| 适用场景 | 作品展示、看界面与体验交互 | 在本机获取和管理自己的岗位 |
| 运行方式 | 双击 HTML，或放到静态网站 | 本地 Python 服务；便携版已包含运行时 |
| 数据 | 固定合成岗位、薪资与证据快照 | 用户本机配置、简历、岗位与已导入证据 |
| 交互 | 翻卡、筛选、证据展开、进度编辑、配置表单与模拟向导 | 实际解析简历、运行已配置适配器、评估和保存进度 |
| 保存位置 | 浏览器演示专用存储；不可用时仅本次打开有效 | 本机配置文件、简历与 SQLite |
| 联网与模型 | 不调用招聘网站、邮箱或模型，不解析真实简历 | 用户主动获取岗位会联网；模型评估为可选启用 |
| 能力边界 | 改档案不会重新计算固定推荐或生成新证据 | 渠道需适配且可能失效；实际资格和投递结果仍需核对 |

### 只想快速看作品

1. 从 [Release 下载前端包](https://github.com/dailaor/job-agent/releases/download/v0.3.0-alpha/JobAgent-v0.3.0-alpha-frontend.zip)。
2. 解压，双击 `JobAgent-frontend-demo.html`；也可打开 `frontend-demo/index.html`。
3. 切换卡片、展开依据、搜索岗位，记录或更新求职阶段。
4. “重置演示”恢复初始配置与记录。不需要填写真实联系方式、上传私人简历或配置 API Key。

前端使用原生 HTML/CSS/JavaScript，无远程字体、CDN 或运行依赖。演示文件里不包含真实简历、用户数据库或凭据。

从仓库复现演示只需 Node.js：

```powershell
node scripts/export_frontend_demo.cjs
```

生成 `outputs/frontend-demo/` 和 `outputs/JobAgent-frontend-demo.html`。正式界面来自 `src/job_agent/static/`，演示适配与合成快照在 `examples/frontend-demo/`；生成结果不提交到 Git。

### 想在本机使用完整版

从 [Releases](https://github.com/dailaor/job-agent/releases/tag/v0.3.0-alpha) 下载 Windows x64 ZIP，解压到可写目录，运行 `JobAgent.exe`。首次启动会建立本机 `data/`。

默认流程：上传或沿用简历 → 核对档案与求职偏好 → 选择已配置渠道获取岗位 → 阅读高推荐卡并核实未知 → 打开原岗位完成提交 → 记录求职进度。

基础便携包不捆绑 Playwright/Chromium，BOSS 浏览器实验能力默认关闭。验证码、登录失效与未知表单应转人工；不承诺全部招聘网站都已适配。

升级前退出旧程序并备份原 `data/`，再将备份放到新 `JobAgent.exe` 旁边。新进度字段自动增量迁移，不需要清空旧记录；不要直接覆盖唯一备份。

配置里的简历路径可能指向旧目录；搬移数据不会自动重写所有绝对路径。若界面提示简历文件缺失，请在我的档案重新上传；解析结果不完整时也应人工核对学历、技能与工作年限。

### 从源码运行完整版

需要 Python 3.11+；以下使用 Windows Python 3.13：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\job-agent.exe init
.\.venv\Scripts\job-agent.exe serve
```

浏览器访问 `http://127.0.0.1:8765`。源码默认配置为 `config.json`、数据库为 `.job-agent/job-agent.sqlite3`，与便携版的 `data/` 布局不同。

## AI 用在哪里

- **默认规则模式**：硬规则与基础能力比较可本地运行，不依赖模型服务。
- **可选 LLM Judge**：用户配置模型接口后，在评估流程中用简历档案、JD 与关联证据辅助双向评分；输出经过本地校验，失败回退规则结果。密钥由环境变量提供，不写入公共模板。
- **岗位情报 RAG**：对通过准入的可追溯文档做脱敏、去重与主题切块，使用 Hashing 向量＋BM25 混合检索，分别组织能力侧与工作体验侧证据。
- **当前推荐页**：读取本机已有事实和有效证据，按当前档案重新核对；查看、搜索和翻卡本身不触发付费模型、外网采集或投递。

RAG 不是“导入帖子就提高准确率”的保证。语料偏差、属性引用错误与多来源冲突仍需检验；当前不宣称生产准确率或录用效果提升。公共仓库和发布包**不附带本机私有情报库**，完整版需要用户自行导入或维护数据。

## 当前能力与边界

| 状态 | 能力 |
|---|---|
| 已交付 | 高推荐单卡与证据展开、完整岗位列表、手工求职进度、档案与设置分离、蓝灰界面、独立前端演示 |
| 已实现，依赖数据与适配 | PDF/DOCX 解析、规则筛选、跨渠道去重、官网岗位采集、可选 LLM Judge、岗位情报导入与检索 |
| 实验 / 环境相关 | BOSS 浏览器沟通、官网写执行器、邮件回执检查；不捆绑登录会话，不绕过访问控制 |
| 尚未开放 | 一键投递、通用浏览器自动填表、面试练习、Offer 对比、自动反馈校准 |

已内置美团、滴滴、快手、腾讯、京东的**校园招聘**公开岗位适配器，不等于覆盖这些公司的全部校招和社招系统。渠道能否正常采集会随站点变化；遇登录、验证码、页面壳或缺少稳定详情时停止并报告原因。

小红书不直接批量抓取；牛客仅处理用户明确提供的单篇公开讨论链接，限速且遇访问控制停止。支持用户人工导入可追溯内容，不接收 Cookie、Token 或账号密码。

下一步优先建设可追溯、可更新的岗位数据库，补充公开岗位、薪酬和团队体验事实及来源时效；再设计基于简历与 JD 的面试练习、追问和复盘反馈。这些是计划，不是当前演示已具备的能力。

## 开发与验证

核心结构：

```text
src/job_agent/
  static/            正式界面、推荐卡和交互
  recommendations.py 当前档案与有效证据的只读决策层
  service.py/web.py   本机 API 与业务入口
  database.py        岗位、执行记录、独立求职进度与事件
  orchestrator.py    发现、评估、规划与实验执行
  connectors/        各官网与浏览器适配器
  knowledge/         情报准入、存储和混合检索
examples/frontend-demo/  演示接口与合成快照
scripts/             导出、预览、测试与便携构建
tests/               离线回归
```

后端离线检查：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

浏览器检查脚本为 `scripts/test_recommendations_ui.cjs`、`scripts/test_frontend_demo.cjs`，需要可用的 Node Playwright 与浏览器；这是开发验收依赖，不是产品运行依赖。

本版覆盖旧库迁移、并发记录、八阶段校验、手工接管和在途证据保留；浏览器覆盖单卡边界、筛选/刷新、键盘作用域、错误恢复、文本/URL 安全与进度持久化。Windows tag 构建由 GitHub Actions 运行，不能把本机通过当作远端通过。验收不代表真实外网投递已经测试完成。
